# 01 · 首页规格

## 1. 命名与外壳

### 1.1 列表项

`lib/ui/app.dart:431` 的 `ShellSection` 新增 `home`，排在 `browse` 之前：

| 序号 | 枚举值 | 图标 | 标签 | 变化 |
|---|---|---|---|---|
| 0 | `home` | `Icons.home_outlined` | 首页 | **新增** |
| 1 | `browse` | `Icons.grid_view` | 点播 | 标签「首页」→「点播」，图标与行为不变 |
| 2..10 | 其余 9 项 | 不变 | 不变 | 不变（总数 10 → 11） |

**为什么枚举顺序必须等于侧栏顺序**：`_SideBar` 用 `selectedIndex: section.index` + `ShellSection.values[index]` 双向映射（`app.dart:1417-1419`），插错位置会让点「点播」亮成「首页」。

**为什么不把 `browse` 改名成 `vod`**：枚举名是内部标识，全仓库 10 处引用都不带用户语义；改名只会制造 diff。只改标签，并在枚举注释里写清「browse = 点播」。

### 1.2 侧栏容量（实测，必须一起改）

`app.dart:227` 的最小窗口是 1024×640，顶栏 64px 之后内容区只有 **576px**。实测（`flutter test`，2026-11-19）：

| 入口数 | 内容区高 576（1024×640） | 640 | 800 |
|---|---|---|---|
| 10（现状） | **溢出 8px** | 正常 | 正常 |
| 11（本次） | **溢出 72px** | 溢出 8px | 正常 |

也就是说 **今天在应用自报的最小窗口下侧栏已经溢出 8px**（只是默认窗口 1280×800 撞不到），加第 11 项会把它变成 72px 的明显破图。

决定：`NavigationRail(scrollable: true)`。理由：一行修复，11 项在 640 高的窗口下变成可滚动而不是溢出，顺带把既有的 8px 缺陷一起修掉；文案与顺序都不动。**不采用**「合并入口（日志并进设置 / 追剧并进收藏）」——那是一次导航信息架构变更，不该搭这次车。

### 1.3 启动默认段

`app.dart:455` 的 `_section = ShellSection.browse` 改为 `ShellSection.home`。

三处**程序化**跳转（`app.dart:608 / 743 / 928`）**保持指向 `browse`**：它们的语义是「导入配置/换站点之后，去点播看这个站点的内容」，不是「回第一屏」。

**不做**「记住上次所在段」：侧栏只有 11 项、且首页是「每次打开都该看一眼」的面，持久化它只会在下次启动时制造「为什么不在首页」的困惑。

### 1.4 页面接缝

`HomePage` **不 import `app.dart`**（避免外壳 ↔ 页面循环依赖，也让页面能在 widget 测试里单独挂载）。它只认三个意图回调：

```dart
HomePage({
  required AppState state,
  required VoidCallback onOpenBrowse,      // 「去点播」「查看全部·点播」
  required VoidCallback onOpenHistory,     // 「查看全部·继续观看」
  required VoidCallback onOpenFollowing,   // 「查看全部·追剧更新」
})
```

`AppShell._buildContent` 里注入 `setState(() => _section = ShellSection.browse/history/following)`。

## 2. 首屏结构

```text
┌ 内容区（顶栏 64 / 侧栏 76 不动）─────────────────────────────┐
│ ┌ Hero（约占内容区高 68%，下限 400，上限 720）──────────────┐ │
│ │  背景：backdrop（无则海报）cover / 顶部对齐 / 底部压暗     │ │
│ │                                      · · ● · ·           │ │ 6px 琥珀指示点
│ │  [2:3 海报]  标题（displaySmall）                         │ │
│ │              年份 · 评分 · 类型                            │ │
│ │              理由行：继续观看 · 第 8 集 · 剩 12 分钟        │ │
│ │              [ 继续播放 ]  [ 查看详情 ]                    │ │
│ │  琥珀进度细线（仅续播类）横贯 hero 底边                     │ │
│ └───────────────────────────────────────────────────────────┘ │
│  继续观看                                    查看全部 →       │  SectionHeader
│  [卡][卡][卡][卡][卡][卡] …（横向，鼠标可拖）                  │
│  追剧更新 ⑤                                  查看全部 →       │
│  [卡][卡][卡] …                                               │
│  个性推荐·TMDB / 个性推荐·豆瓣                 查看全部 →       │
│  [卡][卡][卡] …                                               │
└───────────────────────────────────────────────────────────────┘
```

- 页面参照详情页采用**固定背景 + 一个纵向滚动视图**：16:9 海报在 `Positioned.fill` 中铺满内容区，不随滚动移动；`CustomScrollView` 承载 hero 文案与下方轨道。hero 文案是第一个 sliver，不吸顶、不视差、不在滚动时缩放。
- 固定背景与 hero 共用当前轮播下标，沿用 8 秒节奏、手动切换、悬停停表与减少动效；背景不单独计时。固定图使用 `BackdropScrimKind.page`，下方轨道也能看到图片。只有竖版海报时保留夜空渐变 + 清晰海报，不把竖图拉成宽幅。
- 区间距只有一个来源：`SectionHeader` 的 24px 上留白（与 `DESIGN.md:320` 的收敛一致），区块之间**不加** `SizedBox`。
- 页面左右内边距 24（`AppSpace.xl`）；hero 是满幅——**上下左右都不留白**，只有内容落在 24/24/24/44 的安全区里。

## 3. Hero 规格

### 3.1 尺寸

```
heroHeight = hasBackdrop ? clamp(内容区高, 360, 1000) : clamp(内容区高 × 0.62, 360, 640)
```

| 窗口 | 内容区高 | hero 高 | 首屏还能看到 |
|---|---|---|---|
| 1024×640（最小） | 576 | 400（下限） | 一条轨道标题 |
| 1280×800（默认） | 736 | 500 | 一条轨道的卡片上半 |
| 1920×1080 | 1016 | 691 | 一条轨道完整 |
| 2560×1440 | 1376 | 720（上限） | 一条轨道完整 + 下一条标题 |

上限 720 的理由：再高就只是把一张 16:9 的图放大到糊，而把「下面还有东西」这条信息的成本抬到必须滚动才发现。

### 3.2 素材与裁切

沿用 `TmdbBackdropSlideshow`（`tmdb_detail_view.dart:55`）已经定型的做法，逐条都是既有实测结论，不要重新发明：

| 项 | 取值 | 来源 |
|---|---|---|
| 图片 | `PosterImage(fit: cover, alignment: topCenter)` | `tmdb_detail_view.dart:223-227` |
| 无 backdrop 时 | 用海报兜底（`fallbackUrl`），同样是 cover | `:98` |
| 切换 | `AnimatedSwitcher` 600ms 交叉淡入 | `:193-194` |
| 遮罩 | `TmdbBackdropScrim.hero`：底部压到 `surface` 不透明，顶部 0.42 | `:244-258` |
| 指示点 | 6px 圆点，右下 `right:20 / bottom:16`，当前点 `primary` | `:283-306` |

**裁切重心取顶部**：窗口比素材更宽时 cover 纵向裁掉的部分全部落到底部，而底部本来就被遮罩压到接近不透明——这是 2026-10-23「全屏被截取不好看」的修复结论，直接继承。

**素材来源与降级**（这是本页唯一新增的一条素材规则）：续播/追剧条目的 `vodPic` 是站点给的海报（2:3），拿它当 16:9 背景会把它拉成糊的宽幅。因此：

1. 有 TMDB 身份（`PlaybackHistory.hasTmdbIdentity`，`storage.dart:89`）→ 用 backdrop（`TmdbItem.backdropUrl`）；
2. 没有 → 用海报 cover 兜底 + **强遮罩**（图片本身当作色块，文字主要靠在海报上压暗的一层）；
3. 两者都取不到 → 页面底色（`surface`），不出现破图（`PosterImage` 已有失败兜底）。

### 3.3 内容（贴底）

内容贴着 hero 底部，内边距 `fromLTRB(24, 24, 24, 44)`（44 是给底部指示点让出的安全区，`tmdb_detail_view.dart:265-267`）。

| 元素 | 样式 | 内容 |
|---|---|---|
| 海报 | 2:3，宽约 168，`AppRadius.sm`，发丝边 | 与背景同一部作品的竖版海报；背景是海报兜底时可省略 |
| 标题 | `displaySmall`（不缩放，Metric-Neutral） | 片名 |
| 副信息 | `bodyMedium` / `onSurfaceVariant` | `年份 · 评分 · 类型`（口径复用 `recommendation_meta.dart` 的「年份 · 评分」） |
| 理由行 | `bodySmall`，前面一个 14px 图标 | 三类各一句，见 §7 |
| 主按钮 | `FilledButton`（琥珀） | 续播：「继续播放」；追剧：「从最新一集开始」；推荐：「查看详情」 |
| 次按钮 | `OutlinedButton` | 续播/追剧：「查看详情」；推荐：「去找片源」（打开 `SearchPage`，带入片名与已有 TMDB 身份并自动搜索） |
| 进度线 | 2px，`primary`，宽度 = 剧集进度 | **只给续播类**。这是本页唯一的「星等」用法：它确实在度量一个真实的东西（看到哪儿了） |

进度线为什么放在 hero 底边而不是内容块里：hero 底边是这张幻灯片的「地平线」，进度线压在上面读起来是「这部剧的进度」，放进文字块就变成又一个标签。

### 3.4 组成与排序（详见 02 文档 §2）

- 1–6 张，按「追剧有更新 → 未看完的最近观看」取，跨源按 `recommendationTitleKey` 去重（`core/detail_recommendation.dart:57`）；`buildHomeFeed` 在**推荐一开始就在**的场合（测试、未来的预取）仍会把推荐算进 hero，但页面层的异步合并只追加、不驱逐。
- **hero 只放「已经在你手上的」**（追剧有更新 + 未看完的续播）；推荐只出现在轨道里。落地时改过一版：原稿要求「hero 至少保留 1 张推荐位」，但推荐是**异步后到**的，为它腾位就要驱逐一张本地条目——那是把用户正在读的那一张换掉。「你可能想看」在轨道上本来就更可浏览，不需要占首屏的主位。
- 少于 3 张时不补齐、不重复：2 张就 2 张。指示点与轮播都按 `items.length > 1` 生效，与 `TmdbBackdropRotation.shouldRotate` 同口径——落地时改过一次：原稿写「≤2 不显示指示点」，但那样 2 张时会**无声换图**（没有 dots 就没有「还有一张」的线索），比多点两个点更糟。

### 3.5 自动轮播与暂停

- 间隔 **8 秒**。理由：hero 上要读两行中文（约 20–30 字，3–4 秒），5 秒（`TmdbBackdropRotation.interval` 给纯图片用）没有余量。
- **指针进入 hero 区域 → 停表；离开 → 从头计时**（不复位到剩余时间：简单、可预期，也不会在用户刚读完时立刻跳走）。
- 页面不是当前路由、或 `TickerMode` 关闭 → 停表（直接复用 `TmdbBackdropSlideshow._syncTimer` 的判据，`tmdb_detail_view.dart:141-165`）。
- 系统「减少动态效果」开启（`reducedMotionOf(context)`，`app_motion.dart`）→ **仍然轮播，但切换不淡入**（硬切）。落地时改过一版：原稿写「完全不自动轮播」，那等于把首页的主功能对这类用户直接关死；无障碍要治的是持续运动，不是内容会换。
- 只有 1 张 → 不启动任何 `Timer`（`TmdbBackdropRotation.shouldRotate`），否则 `flutter_test` 会留着 pending timer。

### 3.6 交互与焦点

| 动作 | 行为 |
|---|---|
| 点次按钮（查看详情） | `openHistoryDetail`：切回记录自己的站点 + 带线路/集/进度进详情页 |
| 续播／追剧主按钮 | 续播 → `resumeHistoryEntry`（`playback_resume.dart`）／追剧 → 进详情并定位最新集 |
| 推荐「查看详情」／推荐轨道卡片 | 有 TMDB 身份时打开该作品的 `TmdbDetailPage`；无身份时展示已有推荐资料，不伪造身份，不跳当前站点点播页 |
| 推荐「去找片源」 | 打开站源搜索页，带入作品名及已有身份提示；没有身份时只带标题。详情页的「搜索站源」沿用相同入口 |
| 点指示点 | 跳到该张，停表 |
| 指针悬停 hero | 停表 |
| `←` / `→` | 上一张 / 下一张（hero 区域有焦点时） |
| `Space` / `Enter` | 主按钮（焦点在 hero 上且没落在具体按钮时） |
| 滚轮 | **不接管**：竖直滚轮滚页面。hero 不是横向滚动容器，不做 `_WheelScroll` 转轴 |
| `Tab` | 主按钮 → 次按钮 → 第一条轨道（指示点不进 Tab 序） |

「点击即用」的硬约束：续播与追剧的点击**不得**先弹确认框、不得先要求选线路；站点已不在配置中时按既有 `resumeHistoryEntry` 的可读失败提示处理（`playback_resume.dart:11`），不静默。

## 4. 三条轨道

通用规格：

- 横向 `ListView`，包 `HorizontalMouseDrag`（`scroll_behavior.dart:50`）——鼠标拖得动是 §17.4 的硬要求。
- 卡片宽 / 间距走 `LayoutScale`：续播与追剧用**海报宽**（195 × 档位），推荐卡用 168 × 档位（与详情页推荐行同口径，`DESIGN.md:312`）；间距 12 × 档位。
- 高度一律由宽度推：海报 2:3 + 文字区 40px（`_posterCaptionHeight`，`browse_pages.dart:110`），不许写死高。
- 轨道左端与 hero 左端对齐（24），卡片溢出到窗口右缘之外——横向条不做右内边距，靠滚动暴露「还有更多」。

| 轨道 | 数据 | 卡片内容 | 空则 |
|---|---|---|---|
| 继续观看 | `state.recentHistory(sourceKey: '')`，取未完成（`progress` 在 (0, 0.95)），按 `updatedAt` 倒序，同标题只留最新一条，最多 20 条 | 海报 + 标题 + 琥珀进度条 + 「第 N 集 · 剩 12 分钟」 | 隐藏该轨道 |
| 追剧更新 | `state.followings`，先按「有新集未看」（`latestReleasedEpisode > watchedEpisode`）分组，再按 `nextAirAtMs` | 海报 + 标题 + 「更新至 第 12 集」+ 平台徽标（`FollowingAirData.networks` 到位后补） | 隐藏该轨道 |
| 个性推荐 | `state.recommendationDependencies` 的 `RecommendationRow.tmdb` / `.douban` | 海报 + 标题 + 年份·评分 + 推荐理由（一行，超出省略） | 隐藏该轨道 |

- 「查看全部 →」：继续观看 → 最近观看页；追剧更新 → 追剧页；个性推荐 **不设**——推荐没有独立页，点了无处可去就不放这个入口（一个动作只有一个家）。
- 追剧的播出时间/平台来自 `FollowingAirData`（`following_air_data.dart`，TMDB 6h 缓存）：**先渲染本地已知的「更新至第 N 集」，air data 到位后再补平台徽标与下一集时间**，绝不让轨道等网络。

### 4.1 长按与右键（2026-11-20）

- 首页的个性推荐与热门轨道支持**长按 / 鼠标右键**，不触发单击跳转；左右拖拽仍滚动轨道。继续观看、追剧卡片不改变行为。
- **个性推荐**复用详情页的资料弹窗：海报、来源、已有元信息、简介、推荐理由；有身份时「详情」进入作品详情，无 TMDB 身份时主操作明确改为「去找片源」。
- 「不感兴趣」写入与详情页相同的反馈记录，立即从首页推荐轨道与轮播移除；其他页面写入的反馈也同步生效。按现有反馈存储保留 90 天，不另外保存一套偏好，也不删除观看历史或追剧。
- **热门**使用同一弹窗的榜单形态：标明 360kan 与电影／剧集／综艺榜，展示上游真实名次、已有豆瓣评分和更新信息。缺失字段不编造，过滤后的列表序号不能当名次。
- 热门不显示「推荐理由」「不感兴趣」，不伪装成个性推荐或可直接播放的资源；弹窗主操作「查看详情」，另保留「去找片源」，二者都先关闭弹窗再跳转。仅预览榜单信息不额外查询剧情或片源。
- **热门作品详情**：卡片单击、热门轮播主按钮、弹窗「查看详情」复用同一入口；只在点击时通过现有 TMDB 服务按片名检索，并按电影榜／剧集与综艺榜过滤媒体类型。唯一同名候选直接打开既有 `TmdbDetailPage`；同名多条或只有近似片名时展示候选与年份供选择，不盲选第一条。
- 热门轮播次按钮和弹窗「去找片源」仍走按标题搜索。未配置、网络失败或无匹配结果时显示可恢复说明，允许关闭或找片源；不伪造作品身份、不跳当前站点点播列表。查找期间防重复点击，离开首页后迟到的结果不再跳页。
- 新增弹窗取证：`HOME_CARD_CAPTURE=1 flutter test --no-pub test/home_recommendation_navigation_test.dart` 将深浅主题两类弹窗写到 `.local/home-card-info/`（测试夹具海报为空，验证布局与交互而非影视素材）。

## 5. 状态矩阵

| 状态 | 表现 | 依据 |
|---|---|---|
| 未导入配置 | hero 变成「夜空 + 标题 + 导入配置按钮」的静态块（无图片），三条轨道全部隐藏；顶栏的「导入配置」仍是主入口 | 与 `BrowsePage` 的 `_EmptyHint` 分工一致：整页级空态不居中、不占满 |
| 有配置但本站不可用 | 不影响本页：本页读的是**跨源**历史与追剧 | `recentHistory(sourceKey: '')` |
| 有历史，无追剧/推荐 | hero 用续播（2–4 张），只渲染解锁了的轨道 | 空块隐藏（`docs/phase4/design/04` §3.4） |
| 三者全空 | hero 静态块：「去点播逛逛」主按钮 | 一条出路，不教三遍 |
| 推荐服务未配置（无 TMDB key） | 推荐轨道隐藏，**不**做「去设置里配 TMDB」的引导 | 与 §3.4 一致：空块不占位；配置入口在设置页已有 |
| 推荐请求失败 | 静默隐藏该轨道，不弹 toast、不留错误条 | 推荐是锦上添花 |
| 历史海报取不到 | 卡片显示底色 + 标题（`PosterImage` 兜底），不显示破图 | 既有组件 |
| 页面加载中 | **不显示骨架、不闪空**：本地数据同步可得，第一帧就该是内容 | `AppState.recentHistory` 同步返回 |

## 6. 明确不做的事

| 不做 | 理由 |
|---|---|
| 沉浸模式（隐藏侧栏/顶栏浮起） | 用户选了「保留顶栏与侧栏」；且会推翻 `DESIGN.md:290` 的外壳契约 |
