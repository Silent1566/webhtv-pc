# 站点选择器打开卡顿修复验证

日期：2026-10-12。用户反馈：「点击选择站点按钮每次都会卡一会才能看到弹出层」。

## 结论

弹层出现耗时从 **2009~2643ms** 降到 **236~291ms**（同一 debug 构建、同一数据、
各 4~5 次点击），界面视觉与功能无变化。

## 根因

不在站点列表渲染，而在 `LogService` 的**逐条同步落盘**。

站点选择器打开时会把 170 个站点的内部字段（`key`/`type`/运行时/阶段/不可用原因）
写入日志——这是「UI 不暴露协议内部字段」改造的配套措施（`docs/webhtv-pc-design.md`
§17.1）。当时 `LogService._write` 对**每条**日志做一次
`file.writeAsStringSync(mode: FileMode.append)`。

Windows 上每次 `FileMode.append` 都要重新打开文件、定位到末尾、写入并关闭。
170 次开关文件的系统调用开销远大于 28KB 数据本身：

| 项 | 数值 |
| --- | --- |
| 单条同步追加 | 约 8.5ms |
| 逐条同步追加 170 行 | **1452ms** |
| 一次性追加同一批 170 行 | **1ms** |
| 纯字符串拼接（不落盘） | 0.4ms |

该写入发生在弹层的同一帧流程内（`initState` → `_logInventory`），UI 线程因此被
阻塞 1~2 秒，用户看到的就是「点了没反应，过一会弹层才出来」。

### 真实日志取证

本机 `%LOCALAPPDATA%\webhtv-pc\logs\webhtv-pc.log` 里 `站点选择器打开` 到该块
最后一条 `站点 name=…` 的时间差（21 次点击全部命中）：

```text
2026-10-09T18:49:54  1.978s
2026-10-09T18:49:58  2.439s
2026-10-10T09:27:12  1.368s
2026-10-10T12:50:17  2.018s
2026-10-11T19:10:19  1.311s
2026-10-12T09:26:26  1.361s
2026-10-12T09:27:00  1.453s
（其余 14 次在 1.28~1.56s 之间）
```

## 修复

`LogService` 改为「**内存即时、文件异步批量**」：

- `log()` 只做内存操作（环形缓冲 + 广播流），行进队列；
- 由**单次**定时器按批追加：首条用 0 延迟立即刷出（日志时效性不退化——验收脚本
  轮询日志文件、排查播放问题时不必等批次），后续同批合并，批次间隔 200ms；
- 批次内只做一次「打开 → 追加 → `flush: true` → 关闭」；
- 刷盘是**同步**的（单批 1ms）：不给进程留悬空的异步文件句柄。早期尝试用
  `writeAsString` 异步写，会让 `AppState.dispose()` 之后的测试 `tearDown` 删目录
  报 `OS Error 32 另一个程序正在使用此文件`（已由 `phase5_folder_episodes_test`
  与 `phase2_last_site_test` 抓出）；
- `dispose()` 自己收口补刷，退出不丢日志；
- 写失败仍与早期一致：静默降级为纯内存日志。

## 验证

### 1. 单元门禁

`test/log_service_test.dart`（8 例，全绿）：

- 170 条日志入队耗时 < 200ms（旧实现 1452ms，数量级判别）；
- flush 后全部行按写入顺序落盘（不丢、不乱序）；
- 连续 flush 不重复写；
- 首条日志 50ms 内即可见（0 延迟定时器）；
- dispose 补齐未刷盘日志；
- 内存视图（日志页数据源）与文件内容一致；
- 目录不可写时静默降级、不抛；
- 超 `maxFileBytes` 时轮转为 `.1`。

全量 `flutter test --concurrency=1`：**1490 例全绿**。
`flutter analyze`：`No issues found!`。

### 2. 真实 UI A/B 对照（debug 包 + 隔离数据目录）

方法：把 `%APPDATA%\webhtv-pc` 与 `%LOCALAPPDATA%\webhtv-pc` 复制到
`%TEMP%\webhtv-perf`（关闭同步，避免隔离实例碰局域网），用重定向环境变量启动
debug exe，窗口置顶后用 `SetCursorPos` + `mouse_event` 点顶栏「站点：木偶[盘]」，
并按「对话框标题带区域的像素和变化」判定弹层是否已上屏。

| 版本 | 弹层出现耗时（每次点击） |
| --- | --- |
| 修复前 | 2009ms / 2022ms / 2135ms / 2643ms |
| 修复后 | 236ms / 254ms / 269ms / 280ms / 291ms |

截图对照：修复前 `click-2.png` 与修复后 `click-3.png` 视觉一致——同样的分组 chip
（全部/导/盘/官/4K/磁/采/广/漫/短/音/听/优/APP）、同样的站点行、同样的搜索图标。

### 3. 未影响的部分

- 用户正在运行的 Release 实例（PID 25988）全程未被停止或改写数据；
- 日志文件内容、日志页展示、验收脚本 `tools/phase1/run_windows_acceptance.ps1`
  轮询日志文件的方式均不变；
- 站点选择器本身（搜索、分组、可用状态）零改动。

## 顺带记录的工具事实

- `%TEMP%` 在本机解析到 `F:\temp`（不是 `C:\Users\Maple\AppData\Local\Temp`），
  脚本与截图的绝对路径要用实际解析结果；
- PowerShell 5.1 按 ANSI 读含中文注释的脚本会解析失败（`意外的标记"}"`），
  辅助脚本必须写成纯 ASCII。
