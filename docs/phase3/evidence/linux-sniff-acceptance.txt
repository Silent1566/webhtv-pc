请求头注入实测（夹服务器记录）：
跨 scheme（Referer=https://ref.example/，页面 http://127.0.0.1:PORT/parse/xhr）
  /parse/xhr            ua=WH-PC-SNIFF/1.0  referer=null        ← 页面加载成功（修复前此处零请求）
  /vod/master.m3u8?t=1  ua=WH-PC-SNIFF/1.0  referer=<页面自身地址>
  → 候选拿到、无 ERR_BLOCKED_BY_CLIENT、无「解析页加载失败」
同 scheme（Referer=http://ref.example/）
  /vod/master.m3u8?t=1  referer=http://ref.example/             ← 注入值，不是页面默认 Referer

过程中修掉的真实缺陷（父代理在 lib/core/sniff/chromium_sniffer.dart 修）：
1. 跨 scheme Referer/Origin 不再进 setExtraHTTPHeaders（Chromium 会以
   net::ERR_BLOCKED_BY_CLIENT 拦掉导航），改走 Page.navigate 的 referrer 参数；
2. 主文档 Network.loadingFailed 时先清空全局 Header 重试一次导航，仍失败报
   「解析页加载失败」+ net::ERR_xxx，不再退化成「嗅探超时」。

## 三、未验证 / 已知边界（如实记录）

1. Windows / macOS 的浏览器定位分支（Edge/Chrome 安装路径、执行位判定）本机无法
   运行验证；只做了静态逻辑与 Linux 实测。Windows 侧还需要一次真机复跑。
2. integration_test/t4_sweep_flow_test.dart 的 parser 分类桶已改为
   parseSniffUnavailable（无浏览器=能力缺失），但该门禁需要真实 AT 配置 + 图形会话，
   本机未执行；需在 Windows 复跑一次确认证据行。
3. 无浏览器时的交互文案只做了单测（AppError 分类 + detail 文案），未在真实 UI 上
   点验；Windows 手验步骤见交付摘要。
4. headless 模式下无法完成人机校验交互：引擎只把窗口拉回可见（headed 时生效），
   离屏 headless 时如实发 SniffChallenge 并最终超时；这是设计选择（不绕过验证），
   不是缺陷。
5. 解析器请求超时收紧到 15s（安卓 TIMEOUT_PARSE_DEF）后，慢解析器会更快失败；
   站点接口预算仍是 180s，不受影响（有断言覆盖）。
