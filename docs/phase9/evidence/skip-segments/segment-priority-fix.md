# 片段颜色在单轨内的优先级

## 症状与根因

片头片段被跳过、播放头已进入该区间后，同一段会同时出现已播琥珀色与片段分类色，视觉上像两条轨道叠加。

根因不在片段填充比例，而在原生Slider的轨道几何：Flutter 的 `RoundedRectSliderTrackShape.paint` 默认 `additionalActiveTrackHeight = 2`，已播轨道在`getPreferredRect()`之上、下各扩 1px（`slider_parts.dart:439,489-505`）；缓冲段和我们的片段色都按`preferredRect`高度绘制。于是已播后用琥珀色多露出上下各1px，形成双色边。

修复前工具证据：真实光栅在片头区间内、播放位置50s（已越过片头）时，片段范围外两行的颜色与轨道内背景不一致，精确命中上述1px差异；暗/亮与RTL共4个位置断言失败。

## 采用的优先级

同一条轨道内只允许一个视觉层：

1. 片段分类色最高：有可见片段区间时，该区间整轨高度显示片段RGB，不再把已播/缓存色混在上下。
2. 已播色次之：区间外且播放头已过的位置保持原生琥珀。
3. 缓冲色再次之：区间外已缓冲未播区域保持原生蓝色。
4. 未播轨道最低。

实现只在存在可见片段时把原生轨道的已播额外高度设为0，使三种状态共用同一原生轨道高度，然后按区间覆盖分类色。滑块thumb仍由框架在最后绘制，位于最上层；拖动、命中、几何、悬停与缩略图均未改动。关闭「显示片段高亮」时完全走原delegate，已播轨道保持原生加粗而无片段色。

重叠片段仍按既有输入顺序绘制，本任务不新增片段优先级、透明度或混合模式——用户当前需要的是“不要再出现双色”。
