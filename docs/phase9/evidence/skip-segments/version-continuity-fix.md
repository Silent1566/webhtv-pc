# 多版本播放的同版延续

## 用户可见规则

当前正在播哪一种内容版本，切上一集、下一集、自然连播及跳片尾后就优先沿用：

- 普通／明确「正片」第1集 → 第2集。
- 「番综第1期」→「番综第2期」。
- 已知分辨率、编码、语言、HDR等技术特征也必须一致。
- 只有唯一可靠匹配才自动播放；没有一致项、多个一致项、未知版本或互相冲突的标签，保留选择框。
- 手动选择另一版本后，之后以该所选版别继续匹配；不凭数组位置、文件大小或「版本1」序号猜选。

## 原因与修复边界

原 `EpisodeAggregation.preferredVersion` 仅按分辨率、编码等技术profile匹配。普通「第1集」没有技术profile，直接返回null，所以即使下一组有唯一「第2集」也反复询问。

本轮仅在核心内部增补内容版别匹配，不修改聚合归组、播放页导航接口、线路路由、存储或默认配置：

1. 已确认集号之前的稳定标签可作为版别，集号之后的自由文本视为单集标题。`第1集 星空初遇`→`第2集 月下重逢`不会因为标题不同而丢掉原有唯一同规格匹配。
2. 明确分隔的后置「正片／番综／特别版」标签仍保留，繁简别名归一并去重。
3. 互斥标签冲突先判定，之后才把明确正片归一为普通版。未知与冲突用不同内部状态表示；冲突的当前项或候选项不能靠技术profile兜底自动入选。
4. 之前所有可靠技术profile字段仍需匹配；重复候选、字段缺失或矛盾仍保守询问。

审查发现并已修复的两个反例：把每集标题当稳定版别导致正常续播反复确认；显式正片＋番综归一时漏掉正片标签导致错误自动选番综。两者均先core及真实页面红灯，再最小修复。

## 实际导航证据

真实PlayerPage与隔离媒体transport记录：

```text
normal-1 → normal-2
variety-1 → variety-2
titled-normal-1 → titled-normal-2
titled-variety-1 → titled-variety-2
```

候选乱序时，next、previous、自然EOF及显式片尾完成均只打开正确目标一次，无版本框。无匹配、重复匹配及冲突标签场景实际先显示选择框，取消后仍只有当前URL的一次open并恢复原播放；不只是纯函数结果断言。外部线路路由、原始sourceIndex、季边界及不选择同集alternate的旧回归均保留。
