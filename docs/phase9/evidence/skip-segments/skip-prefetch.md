# 跳段落点预载与安全降级

## 使用与行为

设置 → 播放 → 跳过片段中新增「预载跳过落点」，默认开启，可关闭并持久化。按用户选择允许增加预取流量，但不增加第二播放器，也不隐藏真实缓冲状态。

- 在下一个启用类型的可用片段开始前约 **15 秒实际播放时间**准备落点，按0.25–4倍速换算媒体时间；不开播就下载十分钟后的目标，避免到跳段时缓存早过期。
- 对已解析的点播 HLS 输出清单，准备落点所在分片及之后最多30秒的完整分片、所需key/map；单窗口24MiB先到为止，单会话已完成缓存LRU上限64MiB。直播、未知/不支持的清单不会预载。
- 后台最多一个请求，仅在代理无前台请求时取数。前台到来先真实取消/关闭后台传输，等待该任务结束，再发前台；半包和取消后晚到结果不入缓存。
- 同一媒体安全跳转取消旧队列/在途但保留已下载落点字节；换媒体、关闭开关、会话撤销时清缓存。既有 stop → mpv start option → open 安全定位路径不变。
- 同目标仍新鲜且完整就不重取；过期或缺字节可以重做，但每个目标每会话最多3个窗口、至少1秒冷却、最多64个目标记录，避免暂停/高频位置通知/不可缓存响应导致下载风暴。达到预算时放弃加速，正常播放仍可继续。

## HTTP缓存边界

只保存已授权同会话中的完整200响应；实际收到字节和声明长度校验通过后才入缓存。缓存键不跨会话，不缓存半包、html、编码正文或不支持的范围资源。

保守不复用：no-store/no-cache/private、Pragma、任何Vary、Set-Cookie、未知/重复或无效缓存指令、无效或耗尽的Date/Expires/Age/lifetime。max-age/s-maxage/Expires取最短剩余寿命，扣Age、表观年龄与响应等待；后续以单调时钟计下载/驻留，默认与上限均30秒，不把刷新当TTL续期。

请求携带Cache-Control/Pragma或条件验证头时驱逐旧副本并回原上游路径，相关请求指令按原值转发；命中结果对下游统一no-store，避免重新授予长期缓存。上游禁止缓存时，预载不能让落点无网络，这是有意降级。

## 实际fixture证据

- 有效缓存：Range bytes2–5返回206、4B、content-range2–5/16、video/mp2t；上游目标分片仍只有一次请求。
- 禁止缓存：预取body版本1后，前台拿到新上游版本2，目标上游次数2，不会错误返回旧字节。
- 真实页面闭环：PlayerPage → AppState私有代理 → 预取s3/s4/s5 → 前台落点请求返回4B，上游s3次数未增加。
- 时机：广告600–620s，1倍速下起播和584s不下单，585s下单620s；0.5倍和2倍速使用对应15秒墙钟准备窗。
- 过期：max-age1过期后同目标重新准备，前台直接命中第二版，未发生第三次目标上游请求。
- 并发：严格真实HttpClient委托日志为background open → force-close → close/run done → foreground open，本地调度拥有请求最大1；不把该计数说成远端handler或TCP实测。
- 429：前台或后台收到429都停用当前会话预载并清queue/cache，不重复发起，只有新会话恢复。

## 范围与不能保证的事

这项优化减少的是**已成功准备且未过期分片**的网络等待；没有真实CDN命中率、不同码率/密钥服务及原生解码首帧延迟实测，不承诺所有源零缓冲。服务器释放连接/限流槽没有取消ACK，可能延后并产生首个429，应用只保证本地取消顺序及随后的保守降级；不会为等待远端handler退出阻塞前台。

当前预算是每会话/窗口而非无限缓存；HTTP限制、变体不确定、慢源/短TTL、单流源均可能放弃预载回退原安全播放。没有真实外部影视请求、没有修改用户配置/数据库，也未替换运行包。
