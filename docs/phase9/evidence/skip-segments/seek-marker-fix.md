# 拖动跨缓冲重开后片尾标记丢失

## 症状与根因

用户在同一集拖动一次进度条，播放器走跨缓冲重开后片尾色带消失，也没有自动跳过。日志中重开前有标定结果，重开后没有新的标定记录。

真实 Slider 手势测试复现：拖动前9段，安全 `Media.start` 重开后0段。原因有两层：

1. 同媒体拖动复制 `PlaybackRequest` 时未显式传入TMDB身份；既有 `copyWith` 契约中省略该字段即清空。
2. `_load` 把同媒体重开当作换集，无条件清空标定计划；缺失身份又令重新查询无法开始。

## 修复边界

- 在页面内同媒体的跳转、必要续播、失败续播、重解析、字幕追加及画质复制明确保留TMDB身份；不修改核心 `copyWith` 的清空语义，真正换集仍显式传新身份或null。
- 标定原始段、已处理段、待完成查询按媒体身份归属。同媒体重开保留，按新时长重新折算；换集、线路/URL或画质版本变化时重置。
- 异步结果同时检查媒体身份与独立查询epoch，允许同媒体待查结果跨重开到达，拒绝跨集及A→B→A旧轮结果。
- 版本变化不沿用上一版本raw/cache，不引入拖动时重复查询；URL签名变化保守视为新版本，可能多一次会话查询，避免错套时间轴。

## 实际动作证据

真实 PlayerProgressSlider 拖动与后续自然位置事件：

- 初始500s，已知buffer20s，标定9段。
- 拖动到750s，安全重开；片段仍为9段（含片尾）。
- 自然位置进入805s，命中800–850s片尾，安全重开至850s一次。
- `open.start=[null,750s,850s]`，裸 `seek=[]`，标定请求仅1次；请求仍携带TMDB1/S1/E3。
- 再次上报806s不会重复跳片尾。

数据为隔离fixture，生产provider/计划/页面事件和实际transport动作均参与，不声称真实外部影视解码结果。
