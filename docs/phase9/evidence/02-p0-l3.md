$env:TEMP = "$PWD/.superpowers/tmp9"
$env:TMP  = "$PWD/.superpowers/tmp9"
$env:WEBHTV_FIXTURE_BASE = "http://127.0.0.1:18080"

`com.alexmercerind.media_kit.NativeReferenceHolder.<pid>`，本机 `%TEMP%`
（`F:\temp`）有历史残留，偶发 `OS Error 5` 让测试在加载阶段就失败。

### V4 的两处修正（上一版证据是错的）

1. **旧截图没拍到「片头片尾」**。上一版用 `find.text('片头片尾')` 断言存在，
   但 `SingleChildScrollView` 的 `Column` 会构建全部子项——`findsOneWidget`
   只证明「在树里」，不证明「画在屏幕上」。实际截图停在「速度」区块，
   片头片尾被滚动区裁在下面。现在改为断言
   `menuRect.contains(标题/条目中心)`，窗口拉高到 1440×1600 让整块菜单放下。
2. **旧截图不可能逐字节复现**。全窗口截图包含：烧录在视频里的时间码
   （`00:00:05.960`）与右上角屏显时钟（`19:5x`）。实测两次运行差 4 字节。
   现在只裁菜单本体（`Rect.fromLTRB(300,140,540,1496)`），视频帧与时钟都不在
   证据内；并且连续两帧像素一致才落盘。

## 3. 这一轮**没有**证到的部分（不得当成已完成）

| 项 | 现状 | 原因 / 后续 |
| --- | --- | --- |
| 真实双音轨**切换** | V3 只证「入口存在且不是空菜单」；单轨 fixture 无法验证切轨 | 环境里没有 ffmpeg（`imageio_ffmpeg` 也未安装），无法生成双音轨 MKV；需在具备 ffmpeg 的环境生成 fixture 后补一条 L3 |
| 真实 EOF 触发定时停止 | V2 证的是「定时开 → 必须走停止分支」的契约，不是真实播到结尾 | `sample.mp4` 仅约 6s，且当前用例没有可连播的集列表；补一条「2 集 + 定时本集结束」的窗口用例 |
| 片头跳过的真实 seek 位置 | V1 证了「落库 + 真起播 + 裁决 = 跳 2000ms」，未读回播放器 `position` | 播放器位置未对外暴露；需通过进度文本或加只读测试钩子后再断言 |
| 直播回看的真实播放 | V5 证到「生成地址并进入播放器」，未等出画 | 回看地址带 `start/end` 查询参数，fixture 按路径命中同一媒体；出画断言与 Phase 3 直播出画用例同型，可下轮补 |
