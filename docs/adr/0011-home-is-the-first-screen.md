# ADR 0011 首页成为第一屏（首屏从「挑分类」改为「知道你想看什么」）

状态：接受（Phase A–C 已落地）。日期：2026-11-19。

## 背景

`DESIGN.md` 有两句与本次需求直接相关的结论：

- `:185`「本表面明确拒绝的类别默认排布是『深色海报墙 + 顶部主视觉横幅』：那会把『哪个源能用』沉到二级页面里去，而海报墙本身也无法表达健康度。」
- `:187`「因此源场移到独立页面 `SiteHealthPage`……首页回到『分类条 + 海报网格』的纯粹内容职责。」

两条都成立，但**它们回答的是另一个问题**：`DESIGN.md` 当初要决定的是「源场要不要占首屏」，结论是「不要，因为 170 个站源里 160 个没有采样」。`:185` 里被拒绝的「顶部主视觉横幅」是作为**源场的替代摆法**被拒绝的，不是「首屏永远不能是内容本身」。

与此同时，用户 2026-11-19 的诉求变了：首屏的第一职责从「等用户挑一个分类再看」变成「我已经知道你想续哪部、追哪部、可能想看什么」。这两件事对首屏的要求相反——分类条 + 海报网格要求用户先做一次选择；hero + 轨道则是替用户先做一次选择。

仓库里也已经有可复用的先例：详情页的全幅动态背景（`TmdbBackdropSlideshow`，`tmdb_detail_view.dart:55`）就是用户自己拍的板（2026-10-13「我要的是全屏」、2026-10-23「全屏被截取不好看」），5s 轮播、顶部对齐 cover、底部压暗、6px 琥珀指示点都是实测定型的结果。

## 决策

1. 新增「首页」段（`ShellSection.home`，排第 0 位），首屏是**全幅 hero 轮播 + 三条续播/推荐轨道**；原「首页」改名为「点播」，行为不变。
2. 全屏边界 = **内容区**：顶栏 64px 与侧栏 76px 保持实底不动（用户 2026-11-19 决策），因此 `:290` 的「顶栏与侧栏保持实底」不受影响。
3. 源场**不**回首页。`:187` 的实证结论（160/170 无采样）仍然有效，本次不触碰它。
4. hero 的视觉语言**全部继承**详情页已定型的做法（cover + 顶部对齐 + `TmdbBackdropScrim.hero` 遮罩 + 6px 指示点 + 600ms 交叉淡入），不引入新色、不引入第三方轮播包。
5. 星等琥珀在本页只有一个新用途：续播幻灯片的**进度线**。它仍然「在度量一个真实的东西」（看到哪儿了），符合 The One Accent Rule；不再给它第二个用途。

## 后果

- `DESIGN.md` 需要改三处（Phase C 落地）：侧栏清单（11 项、标签改名）、`Layout` 一节补首屏 hero 高度公式与横向轨道规则、`Open Items` 记「>6 张时的缩略图条未做」。
- `:187` 那句「首页回到分类条 + 海报网格」的措辞需要限定为**点播页**，否则文档与实现长期互相打脸。
- 应用启动后的第一屏不再是「按站点浏览」，因此任何断言「启动即点播页」的用例都要显式先切段（已知一处：`integration_test/mvp_a_flow_test.dart:526`）。
- 侧栏加到 11 项，在本机最小窗口 1024×640（内容区 576px）下溢出 72px（实测），必须同时开 `NavigationRail.scrollable`；这一步顺带修掉既有 10 项时的 8px 溢出。

## 被否决的替代方案

| 方案 | 否决理由 |
|---|---|
| 只改名，不新增首页 | 用户要的是「点击即用」的续播/推荐首屏；改名解决不了这件事 |
| 沉浸式首屏（隐藏侧栏/顶栏浮起） | 用户明确选了「保留顶栏与侧栏」；且会推翻外壳实底契约，把一次页面改动升级成外壳能力改动 |
| 新首页直接复用详情页的 `TmdbBackdropSlideshow` | 它的 `child` 是静态的、索引私有、key 已被集成测试按名查找；首页需要每张自带内容 + 悬停暂停 + 键盘，改它等于把一个已锁死的组件改成双模式 |
| 把 `TmdbDetailBackdrop` 的页面级固定背景直接搬来 | 那是「整页文字浮在图上」的轻遮罩配方，与「首屏压暗保证白字可读」的 hero 配方相反 |
| 引入 `animated_hero_carousel` / `banner_carousel` 一类包 | 仓库已有等价动画实现（`AnimatedSwitcher` 600ms），再引一个包等于多一份要维护的动画与一套新的测试口径 |
