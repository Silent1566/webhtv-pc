# 外部播放器列表：已确认需求

## 用户确认记录

- 每次外调必须先选择播放器；上次使用的路径仅用于预选。
- 在选择框内提供新增、编辑；扫描条目与用户新增条目均可修改名称和程序路径。
- 同名条目用序号区分，同时显示完整路径；相同 exe 路径去重，不同路径全部保留。
- 不猜测版本号；本轮采用用户允许的序号方案。
- 新增与编辑重启后保留，兼容现有 `ui.externalPlayerPath`。
- 所有覆盖仅保存到本应用设置，不修改注册表或其他播放器配置。
- 不支持额外命令参数或脚本；不扩展删除、隐藏、批量管理或独立设置页。
- 修改和构建仅在 dev2；不替换或关闭 beta 程序。

## 列表与持久化规则

1. 扫描遍历所有登记命令和常见目录，不能在同一播放器族第一次命中后停止。
2. Windows 可执行路径按大小写不敏感、分隔符归一化后去重；不得将两个不同路径误合并。
3. 保留现有播放器族顺序，并在族内保持登记命令、默认目录的确定性顺序。
4. 自定义名称是数据，不能改变启动协议或变成命令。PotPlayer 的协议参数仍由程序文件名判断。
5. 新增/编辑只有点击保存才持久化；取消编辑不保存草稿。取消外调不启动、不暂停内置播放、不改变上次选择。
6. 对扫描条目的编辑必须保存原扫描路径作为覆盖锚点；修改程序路径后重新扫描，不得同时重新出现旧条目和编辑后的条目。
7. 多次编辑同一条目不得不断产生新条目；包括选用 B 后再将 B 改为 C，也不能由旧预选路径复活 B。数据层应保持条目身份和上次所选条目的关系。保存后的用户条目即使暂时未被扫描发现也须保持可见、可编辑。
8. 如果只有旧的已选路径，扫描匹配则合并；不匹配则仍能显示这条旧配置，便于修复或重命名。
9. 新增/编辑不能制造另一个条目的重复可执行路径；拒绝保存并在编辑器提示，而不是静默丢失用户名称。
10. 名称须非空，路径须为独立程序文件路径。无效路径不能启动；保存失败保持编辑器及草稿，不假报成功。
11. 保存其他设置段时不得清除播放器配置，未配置过的默认值不得无故固化进设置文件。

## 模块接口契约

现有 `services/external_player.dart` 中的 `ExternalPlayer(name, executable)` 保持兼容，不向 UI 强制引入新模型类型。

```dart
// AppState 新接口；实现归任务 1。
Future<List<ExternalPlayer>> listExternalPlayers();
Future<bool> saveExternalPlayer({
  String? originalExecutable,
  required String name,
  required String executable,
});

// 已有接口保持；仍由使用按钮确认后的路径调用。
String? get externalPlayerPath;
Future<bool> setExternalPlayerPath(String? path);
```

`originalExecutable == null` 表示新增；编辑传当前条目的路径。数据层负责找到已有覆盖并保留最初的扫描锚点，UI 不管理持久化身份。

选择组件接受上述载入/保存回调及预选路径，返回选择的 executable 字符串或取消的 null；自身不启动任何程序。扫描结果的基础名称不含显示序号，序号只由 UI 生成，编辑时不把自动序号写成用户名称。

## 验收

- 同族不同路径的多个版本均出现；相同文件多处登记仅出现一次。
- 同名条目出现可辨识序号，名称和实际路径同时可见。
- 新增、重命名、改路径、再次编辑、重启加载均正确；扫描不会覆盖用户修改。
- 每次外调仍先选择；编辑取消、选择取消、保存失败均无错误副作用。
- 选择框在 Windows 1024×640 与 1440×900 下内容和操作可达，长路径与多条目可滚动。
- 相关单测、界面测试、静态检查与 Windows Debug 构建通过。

## 本轮不作承诺

不以此功能宣称 PotPlayer 实播故障已解决；VLC 同址实播已经通过。此次不继续外部资源实播、不改变 MIME、Range 或代理安全策略。
