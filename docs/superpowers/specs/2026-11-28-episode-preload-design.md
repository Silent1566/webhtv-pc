# 点播下一集预载设计

参考：[FongMi/TV、AndroidX Media3 与 mpv 一手资料](../../reference/episode-preload-research.md)。选用应用内代理短窗口缓存：只预解析不能减少媒体取流等待；mpv 播放列表不能可靠控制时机和片头落点；不引入第二个解码器。

- 沿用默认关闭的「预载下一集」。当前点播已播放并有缓冲余量时，长集在实际可跳到结尾的片尾段之前约 25 秒（按播放速率换算）准备下一集，否则以媒体 EOF 为准。5 分钟内的短集约 3 秒后依次准备最近两集，临近切集可重新准备最近一集；只缓存起播窗口：最近一集约 10 秒、最多 4 个分片及其初始化资源（8 MiB 上限），再后面一集只准备首个分片及其初始化资源（4 MiB 上限）。排除需用户选版本、越季、切站、外部播放器及直播／回看／本地文件／队列。
- 仅当前取流已经受本地代理保护、同站普通 HTTP API 或具备独立会话授权的 JVM 站源可直出点播 HLS 时预载。支持媒体清单和只有一个普通变体的主清单；多变体、独立音字幕、字节范围、直连当前流、解析器、其他运行时和受管桥接保留原流程。前台与候选拥有不同的代理授权，不提前改变当前播放决策；没有新鲜分片时无等待回到正常解析。代理只使用已有授权、缓存规则和串行后台取流，前台与本集跳段优先。候选 JVM 在独立进程预解析，最多一个候选，45 秒内未就绪则释放；命中后同时交接媒体与其弹幕等资产的授权。取消候选时中止 HTTP 播放入口请求或关闭候选 JVM；背景请求的 Cookie／Authorization 等凭据以原始媒体 origin 为准，跨源剥离。
- HLS 不确定或无法安全复用则降级。预载与前台使用同一套去广告规则和启发式清洗；按清洗后的时轴准备分片，后台不记广告统计。仅自动模式、启用片头且下一集具有从零覆盖的有效标定时，计算新集起点；按下一集清单时长校验标定，不能沿用当前集远端片头。手动标定沿用现有优先级。用户显式启动进度、确认模式和非零冷开场不被覆盖。
- 在完全匹配的切集动作中交接同一会话，使用播放器已有的打开时定位。撤销、切源/画质、设置关闭、退出、过期、不可缓存响应和预载失败均不改变正常播放。验收以实际从同一代理读取相同分片且上游请求次数不增加为准，不以请求发出为准。

## 现场预载诊断

按在播决策实际持有的正式站点和服务预载，不能仅按选中站点。历史跨配置续播携带原 `sourceKey`，必须匹配仍有效的原配置服务和站点实例，不能按名称或相同 key 借用当前配置。启动、清单准备、资源拒绝和换集未命中均写入 `[preload]`；诊断不含播放 URL、代理 token 或请求头。只有换集接管候选才写「下一集预载命中」。前台优先、跨配置和缓存安全限制不变。

清单准备总预算 25 秒；轮到后台请求开始后，每份清单单独限时 6 秒。持续前台取流时，预载仍排队而不抢带宽；超时按 `inspection_budget_exhausted` / `transfer_timeout` 分别记录。45 秒只限制 JVM 候选的准备过程，已就绪的候选随会话回收。上游明确允许缓存的下一集资源按上游有效期判断是否可用，不再加本地固定上限；没有明确有效期的资源及其他预取仍采用 30 秒上限。容量限制不变，手动清理会丢弃候选及预载内存，不撤销当前播放授权。

同源且未重定向的主清单和媒体清单在切集接管后可一同复用，保留原有的前台去广告、授权检查和 URI 改写；已缓存清单会作为完整的新实体返回普通 GET 或从 0 开始的开放范围请求。重新验证、过期或规则变更时清除整组清单并回源。日志 `hls-preload-hit` 表示实际使用了预载清单，首帧仍需播放器打开和解码。

清单被前台抢占后，至少退避 250 毫秒，再在原准备时间和字节预算内继续；不因固定的抢占次数放弃清单，不会重试单次传输超时。分片的既有重试限制不变。

跨缓冲跳转仍在同一在播会话时保留已有候选；目标在 25 秒切集窗口内可提前做站点解析，但重开时暂停取流。播放稳定且剩余前台缓冲足够播放 15 秒时，最多一个小体积清单请求可与最多两个前台请求重叠，合计仍受原 256 KiB 清单预算约束；视频分片不能并发。开始重开、缓冲不足或暂停即撤去重叠许可，不等待候选即可自动切集。
