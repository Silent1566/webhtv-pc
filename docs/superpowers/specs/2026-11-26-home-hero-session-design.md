# 首页大推荐会话缓存设计

## 目标与已定约束
用户在同一应用运行中切换首页/点播再返回，应立即恢复已可展示的完整大推荐及当前作品；过期内容在后台更新，不先清空。用户已在对话中要求执行。本轮不改变视觉布局、不保活其他页面、不增加依赖、不提交或推送。

## 架构
AppState 惰性拥有 HomeHeroSession，应用退出时销毁。HomePage 只订阅和显示；现有取数、元数据、图片资格、顺序、推荐加载租约改由会话拥有。页面退出只解除监听，不取消会话在途任务。所有异步结果检查上下文 scope/generation，旧结果不得回写新上下文。

会话保存最多12张完整展示项、当前作品key、推荐/热门结果、元数据结果、图片资格和单个刷新任务。最新历史/追剧每次投影重新绑定，缓存展示字段不能冻结播放进度。页面返回不会重新运行未过期且输入未变化的取数/元数据/图片资格。语义输入变化增量处理；安全/配置/管线/图片请求头上下文变化清除不适用内容，明确屏蔽立即生效。

首3张启动快照维持原行为。复用同一磁盘实现新增独立 session 构造器，最多12张、单图6MiB，总索引上限沿用64KiB；不扩张默认启动读写上限。会话资源缓存只保留压缩图及文件映射，不长期持有全部高清解码位图，当前/相邻项仍走Flutter图片缓存。新图准备好才替换旧图，当前作品的更新延后到切走，后台失败保留旧数据。

## 新鲜度与失败
复用底层推荐缓存时效/豆瓣限流。会话六小时重新验证元数据/热门（无周期定时器，在再次进入/输入变化时触发）；失败只在下一次进入且至少一分钟后重试，旧内容保留。推荐请求种子与反馈有独立稳定签名。播放进度本身不影响缓存签名。单一上下文只能有一个同类任务，不因反复切页重建队列。

## 图片缓存接口（冻结）
保留 HomeHeroStartupCache(directory: Directory)。新增 HomeHeroStartupCache.session({required Directory directory})，拥有独立 home-hero-session-v1 目录、最多12条；read(String scope), save(String scope, Iterable<HomeHeroStartupCandidate>), clear() 与现有默认实例同语义。继承现有scope校验、实际解码资格、符号链接拒绝、原子发布、旧generation写入保护与孤儿清理。不接受任意目录名称。

## 验收
1. 12张加载完成，选第8张，销毁首页并重建：未完成图片复查时仍有12张且同一作品；同输入不重复推荐/元数据/资格请求。
2. 部分加载时离开再返回，继续同一任务，已完成内容不丢。
3. 过期慢刷新、失败、离线：旧列表仍可用；新增成功后追加，当前项不突变。
4. Flutter图片缓存驱逐后可用本地文件实际解码，不依赖网络；启动默认仍最多3张。
5. 配置/身份/字段关闭/屏蔽变化无旧内容或迟到结果串入；继续观看绑定最新进度。
6. 原高清门槛、候选原序/去重、图片失败补位、轨道和等高占位测试保持通过。

## 验证边界
使用确定性widget/存储测试并做Windows Debug构建；不把fixture结果描述成真实外部网络性能。无布局或样式改动，不增加截图门槛；如实际发生视觉布局变更须补同场景截图。
