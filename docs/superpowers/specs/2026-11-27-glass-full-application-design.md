# WebHTV PC 全应用玻璃改造设计

## 已定边界（2026-11-27）
- 用户要求全面改造，明确指出 AppSideBar 未改；不得把共享 AppBar 完成算成页面完成。覆盖应用导航、正文容器、全部设置/管理/诊断页、详情、弹窗/菜单/通知、播放器控件和自绘窗口标题栏。
- 无配置壁纸时提供随明暗主题变化的内置底景；配置 wallpaper/logo 优先。加载或失败回退默认底景，不留空白、不改变前景布局。
- 播放器性能优先：玻璃边缘、染底和交互统一，不对视频强制实时 BackdropFilter。视频图像、字幕/弹幕正文和第三方网页正文不改；应用持有的浏览器外壳仍纳入。
- 保持现有功能、导航顺序、中文文案、键鼠操作和配置/协议/安全边界；不引入依赖，不提交或清理已有脏改动。

## 视觉与架构
沿用深靛/昼间星表与琥珀强调色，不重新命名功能或重排业务。通过一处默认背景、共享玻璃容器及主题化控件建立统一材质。主导航与主操作区明显可见材质；卡片、列表、表单与海报文字保持清晰，可采用致密染底，而不是给每项列表叠模糊。普通页面每个主要面板最多一个裁剪滤镜，嵌套内容不重复模糊。播放器面板禁用背景滤镜。

窗口标题区与应用同主题，提供标题、最小化、最大化/还原、关闭；空白区可拖动、双击最大化，全屏隐藏。保留窗口关闭清理、Escape 退出全屏、最小窗口和系统缩放行为。先以 window_manager 现有接口实现；不能用正常的系统标题栏冒充已改。

## 完成标准
1. 每个 UI 路由/弹层/菜单家族在覆盖表中有落点、源码和验收，不以全局透明颜色冒充实际玻璃。
2. 亮暗主题、有壁纸/无壁纸/壁纸加载失败、1024×640 和用户截图约1280×800 内容尺寸均可操作；所有导航项可达，字号放大不溢出。
3. 首页、侧栏、内容页、设置/管理、确认框/菜单、播放器和标题区留同场景 Before/After；没有可靠 Before 则注明并交 After。
4. 返回、焦点、取消、搜索筛选、导入/切换/错误流程不变；文字常规4.5:1、大字3:1，表单可读。
5. 针对性回归和静态检查通过，Linux Release 重建且运行进程加载新 AOT；Windows/macOS 未真机验证必须明确，不伪造性能或平台验收。
