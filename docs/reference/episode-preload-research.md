# 下一集预载与片头／片尾：一手资料核查

## FongMi/TV：确有下集媒体预载

核查范围：[官方仓库](https://github.com/FongMi/TV)公开默认分支 `fongmi` 的[固定快照](https://github.com/FongMi/TV/tree/e296b5905ddb2ba34914f55c205b8cfb92279bc6)。GitHub REST API 在本次匿名访问中返回限流 403；仓库网页、固定提交的源码包和下列源码均可读。结论不外推到其他分支或发布包。

- **何时预载。** 开启预载和「下集预载」后，当前集累计实际播放约 15 秒便尝试预取播放顺序中的下一集（支持倒序），不是等到片尾才触发。此路径要求 Exo、非直播；需额外解析或需特殊提取器的源等不进入该预载路径。见 [开关](https://github.com/FongMi/TV/blob/e296b5905ddb2ba34914f55c205b8cfb92279bc6/app/src/main/java/com/fongmi/android/tv/setting/PreloadSetting.java#L16-L34)、[触发与候选校验](https://github.com/FongMi/TV/blob/e296b5905ddb2ba34914f55c205b8cfb92279bc6/app/src/main/java/com/fongmi/android/tv/playback/vod/VodPreloader.java#L18-L67)、[预载资格](https://github.com/FongMi/TV/blob/e296b5905ddb2ba34914f55c205b8cfb92279bc6/app/src/main/java/com/fongmi/android/tv/playback/vod/VodPreloader.java#L115-L141)、[播放器限制](https://github.com/FongMi/TV/blob/e296b5905ddb2ba34914f55c205b8cfb92279bc6/app/src/main/java/com/fongmi/android/tv/player/PlayerManager.java#L304-L306)、[提取器限制](https://github.com/FongMi/TV/blob/e296b5905ddb2ba34914f55c205b8cfb92279bc6/app/src/main/java/com/fongmi/android/tv/player/extractor/Source.java#L63-L65)。
- **复用的是媒体，不只是 URL。** 先取站点播放结果，再用 `specifiedRangeLoaded` 从下集的跳片头策略算出的起点预载 10 秒。就绪后由同一会话取回 `getMediaSource()`，封装后加入播放队列，指定跳转可走 `seekToPreloadedMediaItem`。这是内存媒体缓冲复用路径；另有播放当前条目时写入共享磁盘缓存的 `DiskPreloadManager`，播放数据源可读同一缓存，不能据此把下集 10 秒内存预载说成磁盘缓存。见 [起点](https://github.com/FongMi/TV/blob/e296b5905ddb2ba34914f55c205b8cfb92279bc6/app/src/main/java/com/fongmi/android/tv/playback/vod/VodPreloader.java#L129-L141)、[缓冲时长](https://github.com/FongMi/TV/blob/e296b5905ddb2ba34914f55c205b8cfb92279bc6/app/src/main/java/com/fongmi/android/tv/player/exo/ExoPlayerSession.java#L53-L57)、[加载阶段](https://github.com/FongMi/TV/blob/e296b5905ddb2ba34914f55c205b8cfb92279bc6/app/src/main/java/com/fongmi/android/tv/player/exo/ExoPlayerSession.java#L250-L275)、[取回媒体源](https://github.com/FongMi/TV/blob/e296b5905ddb2ba34914f55c205b8cfb92279bc6/app/src/main/java/com/fongmi/android/tv/player/exo/ExoPlayerSession.java#L204-L216)、[挂入队列和切换](https://github.com/FongMi/TV/blob/e296b5905ddb2ba34914f55c205b8cfb92279bc6/app/src/main/java/com/fongmi/android/tv/player/exo/ExoPlayerEngine.java#L273-L318)、[独立磁盘预载](https://github.com/FongMi/TV/blob/e296b5905ddb2ba34914f55c205b8cfb92279bc6/app/src/main/java/com/fongmi/android/tv/player/exo/ExoDiskPreload.java#L26-L69)和[共享缓存读路径](https://github.com/FongMi/TV/blob/e296b5905ddb2ba34914f55c205b8cfb92279bc6/app/src/main/java/com/fongmi/android/tv/player/exo/ExoMediaSourceFactory.java#L94-L104)。
- **片头／片尾。** 手动片头点、续播点、源返回的起点按规则取较晚者；自动模式也把从 0 开始的有效片头段末端计入起点。片头／片尾的自动段读取播放结果的 `skips`；命中有结束点的段时跳到段末，片尾的「直至结尾」段可切下一集，无下一集时跳到末尾。历史中的手动片尾值是离结尾的时长：Exo 的适用源做尾部裁剪，否则控制器在 `position + ending >= duration` 时处理。这里验证的是消费标记的逻辑，不是自动识别片头／片尾，也不是拿片尾点调度预载。见 [返回字段](https://github.com/FongMi/TV/blob/e296b5905ddb2ba34914f55c205b8cfb92279bc6/app/src/main/java/com/fongmi/android/tv/bean/Result.java#L82-L84)、[跳过策略](https://github.com/FongMi/TV/blob/e296b5905ddb2ba34914f55c205b8cfb92279bc6/app/src/main/java/com/fongmi/android/tv/playback/vod/VodSkipPolicy.java#L14-L34)、[尾部裁剪](https://github.com/FongMi/TV/blob/e296b5905ddb2ba34914f55c205b8cfb92279bc6/app/src/main/java/com/fongmi/android/tv/player/exo/ExoPlayerEngine.java#L238-L265)和[段落跳过／切集](https://github.com/FongMi/TV/blob/e296b5905ddb2ba34914f55c205b8cfb92279bc6/app/src/main/java/com/fongmi/android/tv/playback/vod/VodPlaybackController.java#L489-L535)。

## AndroidX Media3：邻近短视频的官方范式

- [官方概念](https://developer.android.com/media/media3/exoplayer/preloading-media/preloadmanager/concepts)以短视频轮播为例：按距当前项的索引距离定优先级，应用给每项定加载阶段；[示例](https://developer.android.com/media/media3/exoplayer/preloading-media/preloadmanager/create)对最近项加载样本，对更远项只选轨或准备源，并非库的默认时长或私有短剧 App 的行为。
- **确实可复用。** 内存阶段用 `specifiedRangeLoaded`；播放时使用同一 Builder 构造的 ExoPlayer 接收管理器的 `getMediaSource()`。固定源码在媒体 period 和起点组成的 key 匹配时交接已预载 period；不匹配会重新建 period。条目登记不代表已有媒体缓冲。见[官方接入](https://developer.android.com/media/media3/exoplayer/preloading-media/preloadmanager/manage-play#fetch-play)、[源对象返回](https://github.com/androidx/media/blob/8c6678b657ede1e7883fc164ef73ed483c7796c3/libraries/exoplayer/src/main/java/androidx/media3/exoplayer/source/preload/BasePreloadManager.java#L223-L236)和[预载媒体交接](https://github.com/androidx/media/blob/8c6678b657ede1e7883fc164ef73ed483c7796c3/libraries/exoplayer/src/main/java/androidx/media3/exoplayer/source/preload/PreloadMediaSource.java#L387-L405)。
- **磁盘是另一阶段。** 所核查版本的 `specifiedRangeCached` 需要 Builder 显式设置 `Cache`；默认源工厂可从该缓存读，换用其他源工厂不能假定命中。仅准备源、选轨，或用新源直接重开 URL，都不等于复用了内存媒体样本。见[官方阶段／缓存配置](https://developer.android.com/media/media3/exoplayer/preloading-media/preloadmanager/create)和[默认工厂的缓存数据源](https://github.com/androidx/media/blob/8c6678b657ede1e7883fc164ef73ed483c7796c3/libraries/exoplayer/src/main/java/androidx/media3/exoplayer/source/preload/DefaultPreloadManager.java#L951-L981)。

## mpv：可复用提前打开的 demuxer，不是定量预载 API

[上游手册](https://github.com/mpv-player/mpv/blob/b0841e8c4d156b8403dc1876c4cbd9011eb583f3/DOCS/man/options.rst#L4484-L4499)：`--prefetch-playlist` 默认关闭，当前 URL 读完后才尝试打开下一播放列表项；不支持经 youtube-dl 包装器解析的 URL，不控制 HLS 项内部的分片预取，也不会预测倒退或改列表。[源码](https://github.com/mpv-player/mpv/blob/b0841e8c4d156b8403dc1876c4cbd9011eb583f3/player/loadfile.c#L1299-L1309)可让提前打开的 demuxer 开始后台缓冲，切换时[匹配则复用，不匹配便丢弃](https://github.com/mpv-player/mpv/blob/b0841e8c4d156b8403dc1876c4cbd9011eb583f3/player/loadfile.c#L1371-L1405)。所以它不是单纯预取 URL 字符串，但不提供指定起点／时长的媒体缓冲交付或持久缓存命中保证。

## 对本项目的核查建议（不选产品策略）

评估时分别验证「播放结果已预取」「播放器实际消费同一份预载媒体」「只提前打开媒体」；可对比切换后的首帧和重复网络读取，而不是以预载请求成功认定复用。片头／片尾标记的来源与契约另见[本项目的实测记录](intro-skip-data-sources.md)，不移植上游阈值。
